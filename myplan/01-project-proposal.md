# 01｜專題企劃：交通配時助手

## 摘要
本專題以單一路口、南北（NS）與東西（EW）兩軸直行車流為對象，以近期到車數、估計排隊與等待狀況建立特徵，使用小型決策樹選擇三種有限配時策略，搭配資料檢查及固定配時回退機制，並在 ARM／FPGA 平台展示與量測。

## A｜Attention Getter（研究動機）
都市路口車流隨早晚尖峰、假日及突發事件變動。固定週期與綠燈比例可能無法應付方向性不均衡，造成某軸大量排隊、另一軸綠燈閒置。FHWA 曾報告配時不適當造成延滯、以及自適應配時具改善潛力；原始提案中的具體百分比需確認來源與適用條件，詳見 [引用查核](05-references-and-claims.md)。

## B｜But / Challenge（問題）
1. **可解釋性**：系統為何優先某個方向？
2. **可驗證性**：與固定配時相比，是否真正降低排隊與等待？
3. **部署成本**：深度強化學習等複雜模型未必適合低成本邊緣運算。
4. **可靠性**：觀測缺失、極端流量或模型異常時如何安全處置？

## C｜Cure / Solution（方案）
- 使用小型、深度受限的決策樹，重視低運算成本與規則可追溯性。
- 僅輸出三類策略：`BALANCED`、`NS_PRIORITY`、`EW_PRIORITY`。
- 透過 ARM 執行特徵處理、推論、顯示和日誌；依板卡情況選用 FPGA 實作計數、計時或簡化比較。
- 使用獨立的資料品質檢查和配時合法性檢查，違規即啟動固定配時回退。

## D｜Development（流程）
1. 在固定視窗取得 NS/EW 到車數、佇列與等待估計。
2. 計算方向差、流量比例和等待壓力。
3. 檢查資料有效性與適用範圍。
4. 決策樹分類三種策略；記錄走過的判斷節點。
5. 經最短／最長綠燈、切換限制檢查後，於下個安全決策邊界套用策略。
6. 若資料或輸出異常，套用預先驗證的固定配時並記錄原因。

## E｜Experiments（實驗）
- 固定配時 vs. 決策樹：共用模擬設定、車流序列、初始條件與隨機種子。
- 核心情境：均衡低流量、均衡高峰、NS 重載、EW 重載。
- KPI：平均等待時間、平均／最大排隊長度、停等次數、通行量。
- 板端：推論延遲、決策頻率、CPU／FPGA 資源、回退事件與主機／板端一致性。
- 各情境以多種子重複試驗，回報平均、變異及退步案例。

## F｜Findings（預期成果）
交付可展示車流狀態、選擇依據與執行結果的原型，並以可重現模擬驗證：簡單可解釋的動態配時能否在部分情境優於固定配時。Surtrac 和廣州研究的外部數據僅作研究動機，不代表本專題已達成或可直接橫向比較。

## 研究成功條件
- **必要**：可追溯決策與 KPI、可重現配對實驗、異常回退測試、板端量測。
- **期望**：在方向不均衡情境改善指標，且均衡情境無不可接受的退步（正式實驗前須定義門檻）。
- **限制**：本階段不推論真實道路的旅行時間、排放或安全改善。
