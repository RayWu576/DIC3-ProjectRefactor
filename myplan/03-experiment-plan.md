# 03｜實驗設計與評估規格

## 假設
- **H1**：不均衡車流下，決策樹能降低等待時間與隊列。
- **H2**：決策樹能在邊緣平台於可接受延遲內推論。
- **H3**：感測異常能可靠觸發回退，且不輸出非法配時。
以上均待實驗驗證。

## 比較組
| 組別 | 政策 |
|---|---|
| `fixed` | 固定週期與綠燈比例（baseline） |
| `tree` | 決策樹選擇三種有限模板 |
| `oracle`（選用） | 離線最佳模板，僅作參考上限 |

各組必須使用相同車流輸入、模擬器設定、相位約束與初始條件。

## 情境矩陣
| ID | 情境 | 重點 |
|---|---|---|
| S1 | `balanced_low` | 雙軸低流量且接近，避免過度調整 |
| S2 | `balanced_peak` | 雙軸高流量且接近，觀察飽和性能 |
| S3 | `ns_heavy` | 南北重載，兼顧東西方向飢餓 |
| S4 | `ew_heavy` | 東西重載，兼顧南北方向飢餓 |
| S5（選用） | `shift` | 優勢方向中途反轉 |
| S6（選用） | `sensor_fault` | 資料缺失、逾時、異常值 |

正式測試前凍結到達分布、流量、飽和流率、模擬時間與配時參數。

## 公平性與重現
1. 固定模擬器版本、拓撲與 KPI 定義。
2. 每情境使用多個預先決定的隨機種子；fixed/tree 採同種子及同車流序列的**配對比較**。
3. 兩組使用一致的 warm-up、統計區間、車輛行為和隨機來源。
4. 訓練／驗證與正式測試資料隔離。
5. 儲存 commit、模型雜湊、設定檔、種子、原始 CSV／JSON 與執行指令。
6. 以每個種子為單位回報平均差、變異、必要時的信賴區間。

## 核心 KPI
| KPI | 定義 | 方向 |
|---|---|---|
| 平均等待時間 | 車輛累計等待秒數／明確定義的觀測車輛數 | 越低越好 |
| 平均佇列長度 | 等間隔取樣之隊列車輛數時間平均 | 越低越好 |
| 最大佇列長度 | 整段觀測中任何一軸最大隊列 | 越低越好 |
| 停等次數 | 車輛從移動轉入停車狀態的次數（需定義速度閾值） | 越低越好 |
| 通行量 | 統計期間通過停止線之車輛數 | 越高越好 |
| 各軸最大等待 | NS/EW 分別檢查最不利等待 | 防止飢餓 |

對越低越好的 KPI：
`Improvement (%) = (KPI_fixed - KPI_tree) / KPI_fixed × 100%`
當 baseline 為 0，改善率不定義；請回報原始值與差額。通行量則用 `(tree - fixed) / fixed`。

## 板端測試
- 延遲：平均、P95、最大值，註明是否含前處理與傳輸。
- 決策頻率：實測與需求目標比對。
- ARM：CPU 利用率、記憶體；FPGA（如有）：LUT、FF、BRAM、DSP、Fmax。
- 正確性：同輸入下主機與開發板輸出一致。
- 可靠性：異常注入、回退次數與原因紀錄。
